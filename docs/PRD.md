บัญชีที่ใช้แต่ละบทบาทตั้งได้ที่ "บัญชีสำหรับลงอัตโนมัติ"; เอกสารลงได้ครั้งเดียว (unique ต่อเอกสาร+เหตุการณ์); เอกสารที่ลงวันที่ในงวดปิดแล้วจะค้างเป็นข้อยกเว้นจนกว่าจะเปิดงวด

## กฎธุรกิจหลัก (Phase 1 บังคับใช้แล้ว)
1. เที่ยวเรือ 1 เที่ยว = เรือ 1 ลำ; เรือมีเที่ยว active ได้ 1 เที่ยว (PREPARING→ARRIVED) — บังคับทั้ง service และ partial unique index; ซ้อนได้เมื่อผู้มีสิทธิ์อนุมัติ+เหตุผล
2. ออกเรือต้องมีไต้ก๋ง + ลูกเรือ ≥1 + เอกสารบังคับครบ/ไม่หมดอายุ + ไม่อยู่เที่ยวอื่น + ใบอนุญาตเรือไม่หมดอายุ; ข้ามได้เมื่อ `trip.approve` + เหตุผล (audit `OVERRIDE`)
3. สัตว์น้ำผูกกับเที่ยวเสมอ บันทึกได้หลังออกเรือจนก่อนปิดเที่ยว; แก้ไขต้องมีเหตุผล (ประวัติ `catch_adjustments`) + optimistic lock (version)
4. น้ำหนักจับ ≠ น้ำหนักขาย: ขายจากล็อต (เที่ยว×ชนิด×เกรด) ได้ไม่เกิน จับ − สูญเสีย − ขายแล้ว; แก้/ยกเลิกรายการจับหรือบันทึกสูญเสียจนต่ำกว่าที่ขายไม่ได้ (advisory lock + ตรวจซ้ำใน transaction)
5. ไม่ลบข้อมูลธุรกรรม: เที่ยว=ยกเลิก, สัตว์น้ำ=void, เอกสาร=REPLACED/CANCELLED, master=soft delete
6. ทุกการเปลี่ยนแปลงสำคัญมี audit log (append-only, trigger กัน UPDATE/DELETE)
7. น้ำมัน: ใช้ไป = คงเหลือก่อนเติม + เติม − คงเหลือเข้าท่า; แยก "วัดจริง/ประมาณการ"
8. ค่าใช้จ่ายแยก "ยืนยัน/ประมาณการ"; สรุปเที่ยวเป็นตัวเลขปฏิบัติการ ไม่ใช่รายการบัญชี

## สมมติฐาน (ปรับได้)
- รอบแจ้งเตือนเอกสาร 90/60/30/7 วัน (ตั้งค่าได้) — เป็นการเตือนธุรกิจ ไม่ใช่ข้อสรุปทางกฎหมาย
- รายการเอกสารบังคับตั้งค่าได้ (Passport, Visa, Work Permit, หนังสือคนประจำเรือ, ใบรับรองแพทย์, สัญญาจ้าง, บัตร ปชช.)
- ยกเลิกเที่ยวได้เฉพาะก่อนออกเรือ
