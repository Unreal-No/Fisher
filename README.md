# Fisher ERP — ระบบบริหารจัดการประมง

ERP สำหรับธุรกิจประมงไทย: ทะเบียนเรือ · เที่ยวเรือ (ออก/เข้า/สรุป/ปิด) · บันทึกสัตว์น้ำ (ใช้งานออฟไลน์ได้) · พนักงาน/แรงงานต่างด้าว + เอกสารและแจ้งเตือนหมดอายุ · ติดตามเรือ GPS (แผนที่/เส้นทาง/geofence/ขาดสัญญาณ) · น้ำมัน (ถังบริษัท, ประสิทธิภาพการใช้) · จัดซื้อ (ใบขอซื้อ→ใบสั่งซื้อ→รับสินค้า) · ขายสัตว์น้ำ (ล็อต, ใบแจ้งหนี้, รับชำระ, ลดหนี้, ลูกหนี้) · ซ่อมบำรุง (แผน, ใบสั่งซ่อม, ชั่วโมงเครื่อง) · เงินเดือนลูกเรือ (กฎค่าตอบแทน, เงินเบิก/เงินกู้, งวด, อนุมัติ/จ่าย, สลิป, ไฟล์โอน) · บัญชีคู่ (ผังบัญชี, สมุดรายวัน, ลงบัญชีอัตโนมัติจากเอกสาร, งวดบัญชี, งบทดลอง/กำไรขาดทุนรายเรือ/งบแสดงฐานะการเงิน/บัญชีแยกประเภท) · เจ้าหนี้ (ใบแจ้งหนี้ผู้ขาย, จ่ายชำระ + หัก ณ ที่จ่าย, อายุเจ้าหนี้) · ธนาคาร (กระทบยอด) · รายงานภาษีขาย/ซื้อ, ภ.ง.ด.1/3/53 · ทรัพย์สินและค่าเสื่อมราคา · ปิดบัญชีสิ้นปี · งบกระแสเงินสด · คลังสินค้า (เบิกเข้าเที่ยว, โอน, ตรวจนับ) · RBAC · Audit log · แดชบอร์ด

Stack: React 19 + Vite + Tailwind v4 + TanStack Query/Table + RHF/Zod · Fastify 5 + Prisma 7 + PostgreSQL 16 · PWA (Workbox) · pnpm monorepo
เอกสาร: [docs/](docs) (PRD, Architecture, DB schema, ER, API, UI, Security, Roadmap)

## Local development
ต้องมี Node ≥22, pnpm 10, PostgreSQL 16

```bash
pnpm install
```

```bash
cp .env.example .env   # แก้ DATABASE_URL / TEST_DATABASE_URL
```

```bash
createdb fisher_dev && createdb fisher_test
```

```bash
pnpm db:migrate && pnpm db:seed
```

```bash
pnpm dev
```

เปิด http://localhost:5173 — ผู้ใช้ทดลอง (เฉพาะ dev, รหัส = `SEED_ADMIN_PASSWORD` ค่าเริ่มต้น `Admin@12345`):
`admin` (ผู้ดูแลระบบ) · `owner` · `ops` (อนุมัติจัดซื้อ) · `captain1` (เห็นเฉพาะเรือ V-001) · `hr` · `buyer` (จัดซื้อ) · `store` (คลัง) · `acc` (บัญชี/เงินเดือน — คำนวณได้ แต่อนุมัติงวดที่ตัวเองคำนวณไม่ได้) · `viewer`
ผู้ใช้เปิด 2FA (แอป Authenticator) ได้ที่ "บัญชีของฉัน"; ผู้ดูแลกำหนดบทบาทที่ต้องใช้ 2FA ได้ที่ "ตั้งค่าระบบ"
ข้อมูลตัวอย่างมีป้าย `[ข้อมูลตัวอย่าง]`; production seed สร้างเฉพาะข้อมูลอ้างอิง + `admin` (บังคับเปลี่ยนรหัส)

## Production (Docker)
```bash
cp .env.example .env   # ตั้ง DB_PASSWORD, PUBLIC_URL, COOKIE_SECURE=true, SEED_ADMIN_PASSWORD, APP_ENCRYPTION_KEY (openssl rand -base64 32 — ต้องมี; อย่าเปลี่ยนภายหลังเพราะ 2FA ที่ตั้งไว้จะใช้ไม่ได้)
```

```bash
docker compose up -d --build
```

```bash
docker compose exec api node apps/api/dist/seed.js
```
API รัน `prisma migrate deploy` อัตโนมัติก่อนเริ่ม · วาง HTTPS (Caddy/Traefik/Cloudflare) หน้า `web:8080` · ไฟล์เก็บที่ volume `files` หรือ S3 (`STORAGE_DRIVER=s3`)

## หมุนกุญแจเข้ารหัส (key rotation)
1. สร้างกุญแจใหม่ `openssl rand -base64 32`
2. ตั้ง `APP_ENCRYPTION_KEYS_OLD=<กุญแจเดิม>` และ `APP_ENCRYPTION_KEY=<กุญแจใหม่>` แล้วรีสตาร์ต API (ระหว่างนี้อ่านข้อมูลได้ทั้งสองกุญแจ)
3. รัน seed (`pnpm db:seed` หรือ `docker compose exec api node apps/api/dist/seed.js`) — เข้ารหัสข้อมูลส่วนบุคคลและ secret ของ 2FA ใหม่ด้วยกุญแจใหม่ (แสดงจำนวนที่เข้ารหัสใหม่)
4. ลบกุญแจเดิมออกจาก `APP_ENCRYPTION_KEYS_OLD` แล้วรีสตาร์ต — เก็บกุญแจเดิมไว้ในที่ปลอดภัยตราบที่ยังต้องกู้คืน backup เก่า

## Backup / Restore
```bash
DATABASE_URL=postgresql://... STORAGE_DIR=/path/to/storage ./scripts/backup.sh ./backups 14
```

```bash
DATABASE_URL=postgresql://... ./scripts/restore.sh backups/db-YYYYmmdd-HHMMSS.dump backups/files-YYYYmmdd-HHMMSS.tar.gz /path/to/storage
```
แนะนำ cron รายวัน + เก็บสำเนานอกเครื่อง + ทดสอบ restore รายเดือน · การกู้คืนต้องใช้ `APP_ENCRYPTION_KEY` ชุดเดิม (ข้อมูลส่วนบุคคลถูกเข้ารหัส)

## Known limitations
- บัญชี: ยอดรับสินค้า/ค่าใช้จ่ายค้างจ่ายล้างผ่านใบแจ้งหนี้ผู้ขาย; รายงานภาษีเป็นข้อมูลประกอบการยื่น (ยังไม่สร้างแบบ ภ.พ.30/ภ.ง.ด. หรือไฟล์ยื่นออนไลน์, ยังไม่ออกหนังสือรับรองหัก ณ ที่จ่าย 50 ทวิ); กระทบยอดธนาคารติ๊กเอง (ยังไม่นำเข้า statement); ภาษีเงินได้หัก ณ ที่จ่ายเงินเดือนกรอกเป็นรายการปรับปรุงในงวด (ยังไม่คำนวณภาษี/ประกันสังคมอัตโนมัติ); ค่าเสื่อมราคาวิธีเส้นตรงรายเดือนเท่านั้น; ทะเบียนทรัพย์สินไม่สร้างรายการซื้อ (บันทึกผ่านใบแจ้งหนี้/รายการบัญชี แล้วตรวจที่ "เทียบทะเบียนกับบัญชี"); งบกระแสเงินสดเป็นวิธีทางอ้อมแบบย่อ;  ลงบัญชีอัตโนมัติทำเมื่อกด "ลงบัญชีทั้งหมด" (ไม่ใช่ทันทีที่เอกสารเกิด); ผังบัญชีและกฎการลงบัญชีควรให้ผู้สอบบัญชีตรวจก่อนใช้จริง
- รายงาน PDF/Excel ทุกโมดูล — ยังไม่ทำ (มี CSV/พิมพ์ในรายงานบัญชี)
- เงินเดือน: ยังไม่คำนวณประกันสังคม/ภาษีหัก ณ ที่จ่าย/OT; ไฟล์โอนเป็น CSV ทั่วไป (ยังไม่ใช่รูปแบบเฉพาะธนาคาร); ส่วนแบ่งเป็น % ต่อคนตามกฎ (ไม่ใช่การแบ่งกองกลาง); ระบบเตือนเมื่อยอดหักเกิน 20% ของรายได้ (`payrollDeductionWarnPercent`) แต่ไม่บล็อก — ต้องตรวจเพดานตาม พ.ร.บ.คุ้มครองแรงงาน ม.76 และให้ผู้เชี่ยวชาญยืนยันกฎค่าจ้างลูกเรือประมง
- ขาย: ยังไม่รองรับคืนเงินลูกค้า (ใบลดหนี้ต้องไม่เกินยอดค้าง); สินค้าที่คืนไม่คืนเข้าล็อต; VAT ค่าเริ่มต้น 0% (สัตว์น้ำสดโดยทั่วไปได้รับยกเว้น — ยืนยันกับผู้สอบบัญชี)
- GPS: รับข้อมูลผ่าน HTTP (generic/OsmAnd-Traccar/AIS push) และมือถือ; ยังไม่มี MQTT bridge และการดึงข้อมูลจากผู้ให้บริการ AIS/VMS (ต้องมี credential); แผนที่ใช้ tile ของ OpenStreetMap (production ควรใช้ผู้ให้บริการ tile ของตนเอง)
- มือถือส่งตำแหน่งได้เฉพาะตอนเปิดหน้าเว็บค้างไว้ (ติดตามต่อเนื่องแนะนำแอป Traccar Client)
- หลังอัปเกรดให้รัน `pnpm db:deploy && pnpm db:seed` (seed เพิ่มสิทธิ์ใหม่ให้บทบาทเดิมโดยไม่ทับที่แก้ไว้)
- อัปเกรดเป็น 0.10.0 ขึ้นไป (Docker): ต้องตั้ง `APP_ENCRYPTION_KEY` ใน `.env` ก่อน `docker compose up` (ใช้เข้ารหัส secret ของ 2FA)
- อัปเกรดเป็น 0.11.0: รัน seed (`pnpm db:seed` หรือ `docker compose exec api node apps/api/dist/seed.js`) เพื่อเข้ารหัสเลขบัตร/เลขบัญชี/เลขเอกสารที่มีอยู่เดิม — **สำรอง `APP_ENCRYPTION_KEY` ไว้ที่ปลอดภัยแยกจาก backup ถ้าหายจะอ่านข้อมูลเหล่านี้และ 2FA ไม่ได้อีก**
- อัปเกรดจากเวอร์ชันก่อน 0.3.0: ค่าเริ่มต้นบทบาทที่เปลี่ยนสำหรับสิทธิ์ที่มีอยู่แล้ว ต้องเพิ่มเองที่หน้า "บทบาทและสิทธิ์" — ผู้จัดการฝ่ายปฏิบัติการ: `purchase.view`, `purchase.approve`, `inventory.edit`; เจ้าหน้าที่จัดซื้อ: `inventory.edit`
- ช่องกรอกวันที่ใช้ date picker ของเบราว์เซอร์ (ปี ค.ศ.); การแสดงผลเป็น พ.ศ.
- Offline: รองรับบันทึกสัตว์น้ำ; ฟอร์มอื่นต้องออนไลน์
- Background job เป็น single-instance (setInterval)
- ยังไม่มี malware scan ไฟล์อัปโหลด / การหมุนกุญแจเข้ารหัส — ดู docs/SECURITY_PLAN.md · ผลทดสอบโหลด: docs/PERFORMANCE.md
- รายงาน PDF ใช้การพิมพ์ของเบราว์เซอร์ (บันทึกเป็น PDF); ส่งออก Excel/CSV ได้ทุกตารางรายงาน
- ไม่ได้รับรองการปฏิบัติตาม PDPA/กฎหมายแรงงาน — ต้องให้ผู้เชี่ยวชาญตรวจ
